CSE 4630: CONTAINERIZATION FOR DEVELOPERS
ASSIGNMENT 3 - Q7
Nginx reverse proxy with student-service and faculty-service

PURPOSE
Route /student to student-service and /faculty to faculty-service. Only the reverse proxy should publish a host port.

1. CREATE PROJECT DIRECTORIES

mkdir -p ~/CFD-Assignment-3/q7/backend1
mkdir -p ~/CFD-Assignment-3/q7/backend2
cd ~/CFD-Assignment-3/q7

2. CREATE backend1/index.html

cat > backend1/index.html <<'EOF'
<h1>Student Service</h1>
<p>This page is served by Backend 1.</p>
EOF

3. CREATE backend2/index.html

cat > backend2/index.html <<'EOF'
<h1>Faculty Service</h1>
<p>This page is served by Backend 2.</p>
EOF

4. CREATE THE USER-DEFINED NETWORK

sudo docker network create college-network

If the network already exists, reuse it rather than creating a duplicate.

5. RUN THE STUDENT BACKEND

sudo docker run -d \
  --name student-service \
  --network college-network \
  --mount "type=bind,source=$PWD/backend1,target=/usr/share/nginx/html,readonly" \
  nginx:alpine

6. RUN THE FACULTY BACKEND

sudo docker run -d \
  --name faculty-service \
  --network college-network \
  --mount "type=bind,source=$PWD/backend2,target=/usr/share/nginx/html,readonly" \
  nginx:alpine

No -p option is used for either backend, so their ports are not published on the host.

7. CREATE nginx.conf

nano nginx.conf

Enter:

server {
    listen 80;

    location = /student {
        proxy_pass http://student-service/;
    }

    location /student/ {
        proxy_pass http://student-service/;
    }

    location = /faculty {
        proxy_pass http://faculty-service/;
    }

    location /faculty/ {
        proxy_pass http://faculty-service/;
    }
}

Save and exit.

8. TEST THE NGINX CONFIGURATION

sudo docker run --rm \
  --network college-network \
  --mount "type=bind,source=$PWD/nginx.conf,target=/etc/nginx/conf.d/default.conf,readonly" \
  nginx:alpine nginx -t

9. RUN THE FRONTEND REVERSE PROXY

sudo docker run -d \
  --name frontend \
  --network college-network \
  -p 8080:80 \
  --mount "type=bind,source=$PWD/nginx.conf,target=/etc/nginx/conf.d/default.conf,readonly" \
  nginx:alpine

10. VERIFY ALL CONTAINERS

sudo docker ps
sudo docker network inspect college-network

11. TEST THE STUDENT ROUTE

curl -i http://localhost:8080/student

Expected page content:
<h1>Student Service</h1>
<p>This page is served by Backend 1.</p>

12. TEST THE FACULTY ROUTE

curl -i http://localhost:8080/faculty

Expected page content:
<h1>Faculty Service</h1>
<p>This page is served by Backend 2.</p>

13. VERIFY PORT PUBLISHING

sudo docker port frontend
sudo docker port student-service
sudo docker port faculty-service

Only frontend should have a published host port.

CONCEPTS
- A reverse proxy accepts client requests and forwards them to backend services.
- A user-defined bridge network provides container-name DNS resolution.
- proxy_pass specifies the upstream service.
- The trailing slash in proxy_pass affects how the matching URI prefix is forwarded.
- Backends need not publish host ports when only the proxy should be accessible.
