
CSE 4630 - CONTAINERIZATION FOR DEVELOPERS
DOCKER ASSIGNMENT 1 - EXPLANATION AND TROUBLESHOOTING

==================================================
Q1: VERIFY DOCKER INSTALLATION
==================================================

1. sudo docker --version
   Displays the installed Docker CLI version.

2. sudo docker version
   Displays detailed Docker client and server version information.

3. sudo docker run hello-world
   Runs a test container to verify that Docker can execute containers.
   Docker downloads the image if it is not already available locally.

Expected result:
The output should contain "Hello from Docker!"

Important:
If the CLI works but the daemon is unavailable, docker version
or docker run may report a connection error.


==================================================
Q2: NGINX CONTAINER AND PORT MAPPING
==================================================

1. sudo docker pull nginx
   Downloads the Nginx image from a Docker registry.

2. sudo docker run -d --name mynginx -p 8080:80 nginx

   docker run  : Creates and starts a new container.
   -d          : Runs the container in detached mode.
   --name      : Assigns the name mynginx.
   -p 8080:80  : Maps host port 8080 to container port 80.
   nginx       : Specifies the image.

3. sudo docker ps
   Displays currently running containers.

4. sudo docker port mynginx
   Displays the published port mappings of the container.

5. sudo docker logs mynginx
   Displays the container's logs.

Open http://localhost:8080 in a browser to test Nginx.

Expected result:
The Nginx welcome page should appear.

Important concepts:
An image is a template used to create containers.
A container is an instance of an image.
Port mapping makes a container service accessible through a
published host port.

Common errors:
- If the name mynginx already exists, inspect it using:
  sudo docker ps -a

- If port 8080 is occupied, Docker may fail to start the container.
  Check the error message before changing the port.

- If the browser cannot connect, check:
  sudo docker ps
  sudo docker logs mynginx
  sudo docker port mynginx


==================================================
Q3: CREATE AND MOUNT A DOCKER VOLUME
==================================================

1. sudo docker volume create studentdata
   Creates a named Docker volume called studentdata.

2. sudo docker volume ls
   Lists the available Docker volumes.

3. sudo docker run -it --name ubuntu1 -v studentdata:/data ubuntu bash

   -it                    : Opens an interactive terminal.
   --name ubuntu1         : Names the container ubuntu1.
   -v studentdata:/data   : Mounts studentdata at /data.
   ubuntu                 : Specifies the Ubuntu image.
   bash                   : Starts a Bash shell.

Commands executed inside the container:

cd /data
Moves to the mounted directory.

pwd
Displays the current directory. Expected output: /data.

ls
Lists the contents of the directory.

echo "Hello Docker" > test.txt
Creates test.txt containing "Hello Docker".

cat test.txt
Displays the contents of the file.

exit
Exits the container shell.

Important concept:
A Docker volume stores data independently of the container.
The volume name is studentdata. The path /data is the mount
location inside the container.


==================================================
Q4: CREATE A DOCKER NETWORK
==================================================

1. sudo docker network create college-net
   Creates a Docker network named college-net.

2. sudo docker network ls
   Lists the available Docker networks.

3. sudo docker run -dit --name container1 --network college-net ubuntu bash
   Creates and starts container1 on college-net.

4. sudo docker run -dit --name container2 --network college-net ubuntu bash
   Creates and starts container2 on the same network.

   -d              : Detached mode.
   -i              : Keeps standard input open.
   -t              : Allocates a pseudo-terminal.
   --network       : Connects the container to the specified network.

5. sudo docker ps
   Verifies that both containers are running.

6. sudo docker network inspect college-net
   Displays network details and the containers attached to it.

Important concept:
Containers connected to the same user-defined bridge network
can communicate with each other. Docker DNS can resolve their
container names on that network.

Common errors:
- If a container name already exists, inspect it using:
  sudo docker ps -a

- If a container is not running, inspect its status and logs.
- If the network already exists, inspect it using:
  sudo docker network inspect college-net


==================================================
Q5: VERIFY VOLUME PERSISTENCE
==================================================

1. sudo docker rm ubuntu1
   Removes the stopped container ubuntu1.

   If it is still running, stop it first:
   sudo docker stop ubuntu1

   Then remove it:
   sudo docker rm ubuntu1

2. sudo docker ps -a
   Verifies that ubuntu1 has been removed.

3. sudo docker volume ls
   Verifies that studentdata still exists.

4. sudo docker run -it --name ubuntu2 -v studentdata:/data ubuntu bash
   Creates a new container using the same volume.

Commands executed inside ubuntu2:

cd /data
Moves to the mounted volume directory.

ls
Lists the files stored in the volume.

cat test.txt
Displays the contents of the file created through ubuntu1.

Expected output:
Hello Docker

Conclusion:
The file remains available because it was stored in the named
Docker volume rather than only in the first container's writable
layer.

Important:
Do not remove studentdata before completing this experiment.
The same volume must be mounted into ubuntu2 to verify persistence.


==================================================
GENERAL DOCKER TROUBLESHOOTING
==================================================

Check Docker CLI version:
sudo docker --version

Check client and server:
sudo docker version

List running containers:
sudo docker ps

List all containers:
sudo docker ps -a

List images:
sudo docker images

List volumes:
sudo docker volume ls

List networks:
sudo docker network ls

View container logs:
sudo docker logs CONTAINER_NAME

Inspect a container:
sudo docker inspect CONTAINER_NAME

Inspect a volume:
sudo docker volume inspect VOLUME_NAME

Inspect a network:
sudo docker network inspect NETWORK_NAME

Stop a container:
sudo docker stop CONTAINER_NAME

Start an existing stopped container:
sudo docker start CONTAINER_NAME

Remove a stopped container:
sudo docker rm CONTAINER_NAME

Enter a running container:
sudo docker exec -it CONTAINER_NAME bash

Remember:
docker run creates and starts a new container.
docker start starts an existing stopped container.
docker exec runs a command inside an existing running container.
docker stop stops a container without removing it.
docker rm removes a container.
Named volumes normally survive container removal.
